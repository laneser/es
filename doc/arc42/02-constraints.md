# 02 限制條件

## 技術限制

### LPC，不是 C

副檔名是 `.c`、語法看起來像 C，但它是 LPC：有 `mapping`（`([ ])`）、
陣列（`({ })`）、`mixed` 動態型別、`->` 跨物件呼叫（`call_other`）、
`varargs`、`nosave`、`nomask`。沒有指標、沒有手動記憶體管理、沒有標頭檔/實作分離。

編輯器對它幾乎沒有幫助 —— `.vscode/c_cpp_properties.json` 把 `.c` 當 C89 處理，
並刻意把 `C_Cpp.errorSquiggles` 關掉，因為那些紅線全是假的。

### 驅動決定一切

mudlib 能做什麼，完全受驅動提供的 efun 與 apply 介面限制。升級驅動就是
換掉腳下的地板 —— 這次從 FluffOS 2017 升到 v2026.0901.0，踩到的相容性問題
全部記錄在 [09 架構決策](09-architecture-decisions.md)。

其中有些限制無法用設定繞過，只能改 mudlib。例如 `ref` 在新版是保留字，
這是驅動的**編譯期** `#define`（`src/base/internal/options_internal.h`），
執行期設定檔關不掉。

### Lazy 編譯

一個 `.c` 檔要等到有人真的用到它（`load_object`、`call_other`、`new`）
才會被編譯。好處是開機快；代價是**壞掉的檔案可以潛伏很久**，
而且升級驅動之後沒有任何東西會主動告訴你哪些檔案從此編譯不了。
`lest` 就是為了對抗這件事而存在（見 [10 品質與測試](10-quality-and-testing.md)）。

### 單一程序

整個世界跑在一個程序、一個執行緒裡。沒有平行、沒有鎖，但也意味著
**任何一段 LPC 跑太久都會卡住所有人**。驅動用 eval cost 上限
（`etc/fluffos.cfg` 的 `maximum evaluation cost`）強制中斷失控的程式碼。

## 編碼：一段三次轉換的歷史

這是理解這個 codebase 很多怪異之處的關鍵。

```
Big5（1994，台灣原版）
  → GBK（簡體化，此時已有字元遺失）
    → UTF-8 + 繁體（2026，本次）
```

留下的痕跡：

- **殘留的轉義反斜線。** Big5 有大量漢字的第二個位元組是 `0x5C`（反斜線），
  會被編譯器吃掉，所以原作者在那些字後面補了 `\`。轉到 GBK 之後這些反斜線
  失去意義，轉到 UTF-8 更是純粹的顯示垃圾。本次清掉 3431 處，
  還留著 27 處行尾續行型與 59 處雙反斜線型語意不明確的。
- **`□`（U+25A1）缺字。** 更早的轉碼就已經遺失的字元，原有 945 處。
  已依上下文補回 690 處（最常見的是 裡／屍／焰／鎧／鍊／榻／豔），
  剩 255 處。清單與成因見 [`missing-chars.md`](missing-chars.md)。
- **`data/attic/` 裡 16 個檔含 U+FFFD**，來源是原檔本身的壞位元組。

**LPC 識別字只能用 ASCII。** 函式名、變數名不能用中文，
中文只能出現在字串與註解裡。

## 組織與歷史限制

### 沒有原作者

這份 mudlib 的作者散佈在 1992–2001 年間的三個國家，沒有人能問。
檔頭的修改紀錄是唯一的口述歷史，所以**既有的檔頭不覆蓋、不刪除**。

原本的慣例是改檔時在檔尾續寫 `// <date> <name> - <what>`。那是沒有版控時
唯一能留下脈絡的辦法，現在已經停用——新的改動說明寫進 git commit message。
既有的 183 行紀錄留在原地（見 [ADR：停用檔尾修改紀錄](09-architecture-decisions.md)）。

### 大量死碼與備份檔

樹裡混雜著 `*.mad`、`*.old`、`*~`、`*.new`、`*.before_stasia`、`guild-bak.c`、
`test_master.c` 這類檔案。它們不會被載入，但會出現在 grep 結果裡，
**改錯檔案是這個 repo 最常見的錯誤**。判斷哪個是活的，以 `include/*.h`
裡的巨集指向的路徑為準。

還有更隱蔽的一種：`/adm/simul_efun/` 底下有五個檔案（`message.c`、`help.c`、
`lines.c`、`cat.1208.c`、`data.1208.c`）**根本沒有被 `/adm/obj/simul_efun.c`
include**，改它們不會有任何效果。這在本次升級中實際造成過一次誤判。

### 遊戲是活的

`data/` 底下是玩家存檔與留言板歷史，共 644 個 `.o` 檔、6.9MB。
它們是執行期產物但被 git 追蹤 —— 意思是跑過遊戲之後 `git status` 一定不乾淨。
commit 前要確認沒有把測試痕跡一起送出去。
