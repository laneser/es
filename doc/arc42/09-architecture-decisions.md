# 09 架構決策

這一章記錄 **2026 年 9 月從 FluffOS 2017 升級到 v2026.0901.0** 時的每個取捨。
格式刻意簡短：脈絡 → 決定 → 後果。

---

## ADR-01 全樹轉為 UTF-8 繁體中文

**脈絡**　原本是 GBK 編碼的簡體中文，而更早是 Big5 繁體（台灣原版）。
現代終端機與編輯器預設 UTF-8，GBK 造成持續的摩擦（client 要特別設定、
工具鏈處處要轉碼）。

**決定**　一次性轉成 UTF-8 + 繁體。編碼用 `iconv` 機械轉換；
簡轉繁用 OpenCC `s2tw` 全量轉換，再針對「一簡對多繁」的選字逐詞人工校對。

**後果**
- 7636 個檔案轉碼，零殘留、零損壞
- 253 處 OpenCC 選字錯誤被人工修正（隻要→只要、髮出→發出、曆史→歷史…）
- 清掉 3431 處 Big5 時代的殘留轉義反斜線
- 少數 `□` 缺字是更早 Big5→GBK 時代就遺失的，**無法自動修復**，需人工補
- `data/attic/` 16 個檔含 U+FFFD，來源是原檔的壞位元組

**沒有採用的做法**　用 LLM 逐檔翻譯。7000 個檔案的成本與風險都不合理，
而且 OpenCC 是專為此設計的確定性工具。LLM 的價值在校對歧義字，不在翻譯。

## ADR-02 用 devcontainer 從 source 建驅動，版本釘死

**脈絡**　repo 原本附一個 `mudos.exe`（Windows PE32，FluffOS 2017），
在 macOS/Linux 上無法執行。

**決定**　`.devcontainer/Dockerfile` 以 Ubuntu 24.04 從 GitHub 建置
指定 tag 的 FluffOS，`ARG FLUFFOS_VERSION` 釘死版本。刪除 `mudos.exe`。

**後果**　任何平台都能一致地啟動；代價是第一次建置約 3 分鐘。
**不要改用 master 分支** —— 這個 mudlib 對驅動行為極度敏感。

## ADR-03 保留舊語意，而不是改寫舊程式碼

**脈絡**　FluffOS 2019 以後把許多原本是編譯期 `#define` 的行為改成執行期開關，
預設值多半是「新的、合理的」那個，與這個 mudlib 寫成時的假設相反。

**決定**　在 `etc/fluffos.cfg` 明確設定成舊語意
（`sane explode string: 0`、`old type behavior: 1`、`old range behavior: 1`、
`this_player in call_out: 1`…），而不是去改幾千個檔案。

**後果**　升級成本大幅降低。代價是這些設定變成隱性契約 ——
未來若有人「順手把設定改成預設值」，會在難以預料的地方壞掉。
所以那些項目在設定檔裡都加了註解說明理由。

## ADR-04 密碼相容 + 就地升級，而不是強制重設

**脈絡**　FluffOS 2019 以後 `crypt()` 改走系統 crypt()。舊存檔的密碼是
舊驅動內建演算法的產物（41 個字元、不以 `$` 開頭），新版 `crypt()` 認不得，
**所有既有帳號都登入失敗**。

**決定**　新增 simul_efun `verify_password(pass, stored)`，新舊格式都試
（舊格式用新版仍保留的 `oldcrypt()` 驗），回傳 2 代表「密碼正確但存的是舊格式」，
`logind.c` 據此把該帳號的密碼就地升級成 SHA512。

**後果**　玩家無感，第一次登入自動完成遷移。全站 5 個密碼驗證點統一走這個入口。

**沒有採用的做法**　強制所有人重設密碼 —— 這個 MUD 的玩家早就散了，
沒有管道通知；而且 email 欄位多數是空的。

## ADR-05 `ref` 改名，而不是改驅動

**脈絡**　`ref` 在新版是保留字（宣告傳參考的參數用）。
`/adm/daemons/ref_d.c` 因此整個編譯失敗，而它被 `/cmds/object` 與
`/cmds/open` 下大量指令 inherit —— 一個檔案掛掉連帶 33 個檔案陣亡。

**決定**　把 mudlib 裡當識別字用的 `ref` 改名為 `refn`（7 個檔案）。

**後果**　乾淨，未來升級無痛。

**沒有採用的做法**　patch 驅動的 `options_internal.h` 把
`REF_RESERVED_WORD` undef 掉。那會讓這份 mudlib 綁死在一個魔改過的驅動上，
每次升級都要重新 patch。

## ADR-06 相對路徑的 include 一律用雙引號

**脈絡**　555 處 `#include <../foo.h>` 或 `#include <foo.h>`（同目錄）。
角括號代表「從 include 搜尋路徑找」，而 `include directories` 只有 `/include`，
所以會被解析成 `/include/../foo.h`，找不到。舊驅動對此寬容。

**決定**　判準是「`/include/` 下找不到、但相對於該檔案找得到」才改成雙引號，
所以 `<mudlib.h>`、`<config.h>` 這些真正的系統標頭不受影響。

**後果**　`/d/island` 從 251 個載入失敗降到 17、`/d/deathland` 降到 0。
這個問題會連鎖放大 —— 地圖式虛擬房間載入時要 clone 區域裡的 NPC，
NPC 因 include 失敗而編譯不了，整片地圖就跟著掛掉。

## ADR-07 `compress_obj.h` 改用 `base_name()` 而非 `__FILE__`

**脈絡**　`__FILE__` 在舊驅動指「最外層的主檔案」，新驅動指「當前正在處理的檔案」。
`/include/compress_obj.h` 是一段被貼進 `create()` 的程式碼，裡面的
`set_default_ob(__FILE__)` 於是變成 `/include/compress_obj.h` 自己。

**決定**　改用 `base_name(this_object())`，對 clone 物件回傳不含 `#編號` 的
blueprint 路徑。

**後果**　45 個使用它的物件一次修好。另外 16 個**直接**在自己的 `.c` 裡寫
`set_default_ob(__FILE__)` 的檔案不受影響 —— 那裡的 `__FILE__` 展開成該檔自己，
本來就是對的。判斷規則是「`__FILE__` 出現在 include 檔裡就要改」。

## ADR-08 防重入旗標立在函式最前面

**脈絡**　`die()` 中途拋出執行期錯誤時，屍體已經複製出來但 ghost 還沒接手，
`heart_beat` 每秒重新呼叫 `die()`，於是每秒多一具屍體。
原本的防護只檢查 `link_data("dead")`，而連線一中斷它就一律回 0。

**決定**　改用物件自身的 temp 旗標，且**立在函式最開頭**，
每個「其實沒死」的分支（巫師不朽、PK_ZONE）在 return 前清掉它。

**後果**　任何未預期的錯誤都只會發生一次。這個模式適用於所有被
`heart_beat` 週期呼叫的函式。

## ADR-09 指令佇列一次心跳清完

**脈絡**　`heart_beat()` 每次只 `run_cmds()` 一個指令，指令回應延遲
直接等於心跳間隔（實測 0.91 秒）。

**決定**　改成迴圈清空佇列，上限取佇列大小 32（避免指令本身又推進新指令時空轉）。
只動指令回應，不動 `MAX_TICK` 所控制的戰鬥節奏。

**後果**　指令回應 0.91 秒 → 0.04 秒；戰鬥回合維持 8.5 秒。
副作用是玩家可以貼一串指令瞬間執行 —— 原本的佇列有節流效果，現在沒了。

## ADR-10 測試框架自己寫（lest）

**脈絡**　LPC 沒有標準測試框架。FluffOS 自帶的 `testsuite/` 是測驅動本身的。
而 lazy 編譯讓壞掉的檔案可以潛伏很久。

**決定**　寫 `lest`：第一層對每個 `.c` 做 `load_object()` 抓編譯期錯誤，
第二層對有 `xxx.spec.c` 的檔案跑 jest 風格的斷言測試。

**後果**　第一次掃核心目錄就找出 66 個載入失敗，其中 33 個追到同一個根源。
限制是**抓不到執行期型別錯誤** —— 這次真正咬人的幾個 bug 它一個都攔不下來，
那些要靠實際遊玩加上讀 `debug.log`。

見 [10 品質與測試](10-quality-and-testing.md)。
